تصرف كأنك مهندس برمجيات Full-Stack خبير في بناء تطبيقات إسلامية دقيقة وحساسة المحتوى.

أريد بناء تطبيق وموقع متكامل باسم:
“القرآن الكريم”

المشروع:
تطبيق ويب + قابل للتحويل لاحقًا إلى تطبيق iOS وAndroid، يعرض المصحف الشريف كاملًا بصور الصفحات، مع النص القرآني، والتفسير عند الضغط على الآية، وتجربة قراءة احترافية جدًا.

مهم جدًا:
هذا تطبيق قرآن كريم، لذلك الدقة أولوية قصوى.
لا تستخدم أي مصدر عشوائي.
لا تضف آيات أو نصوص من عندك.
استخدم APIs موثوقة فقط، واجعل مصادر البيانات قابلة للتغيير من ملف Environment Variables.

المصادر المقترحة:
1. Quran.com API للنصوص والآيات والبحث.
2. Quranpedia أو مصدر موثوق لصور صفحات المصحف إن كان متاحًا.
3. مصدر تفسير موثوق لتفسير ابن كثير.
4. يجب وضع طبقة تحقق وتنبيه إذا فشل تحميل النص أو التفسير.

الميزات الأساسية:
1. عرض جميع سور القرآن الكريم.
2. عرض صفحات المصحف الشريف كصور.
3. التنقل بين الصفحات.
4. اختيار السورة.
5. اختيار الجزء.
6. اختيار الحزب.
7. البحث باسم السورة أو رقم الآية.
8. عند الضغط على آية يظهر تفسيرها فقط.
9. التفسير الافتراضي: تفسير ابن كثير.
10. إمكانية إضافة تفاسير أخرى لاحقًا.
11. حفظ آخر صفحة قرأها المستخدم.
12. وضع علامات مرجعية Bookmark.
13. الوضع الليلي والنهاري.
14. تكبير وتصغير الصفحة.
15. تصميم عربي RTL كامل.
16. تجربة قراءة هادئة وخالية من التشتيت.

طريقة عرض التفسير:
عند ضغط المستخدم على آية:
- افتح Bottom Sheet أو Side Panel أنيق.
- اعرض:
  - اسم السورة.
  - رقم الآية.
  - نص الآية.
  - تفسير ابن كثير لهذه الآية فقط.
- لا تعرض تفسير السورة كاملة.
- أضف زر إغلاق واضح.
- أضف Loading State أثناء جلب التفسير.
- أضف Error State إذا تعذر تحميل التفسير.

الصفحات المطلوبة:
1. الصفحة الرئيسية.
2. صفحة المصحف.
3. صفحة السور.
4. صفحة الأجزاء.
5. صفحة البحث.
6. صفحة العلامات المرجعية.
7. صفحة آخر قراءة.
8. صفحة الإعدادات.
9. صفحة حول التطبيق ومصادر البيانات.

التصميم:
- اسم التطبيق: القرآن الكريم.
- تصميم احترافي جدًا.
- ألوان هادئة وفاخرة.
- خلفية بيضاء مع لون ذهبي أو أخضر إسلامي هادئ.
- دعم الوضع الليلي.
- خط عربي واضح ومريح.
- واجهة RTL بالكامل.
- مناسب للجوال والويب.
- لا تستخدم زحام بصري.
- ركز على تجربة قراءة نظيفة ومحترمة.

قاعدة البيانات:
استخدم قاعدة بيانات منظمة لحفظ بيانات المستخدم فقط، وليس لتعديل نص القرآن.
الجداول:
- users
- bookmarks
- reading_progress
- app_settings
- tafsir_cache
- audit_logs

ملاحظة:
يمكن تخزين Cache للتفسير والآيات لتحسين الأداء، لكن لا يتم تعديل النصوص الأصلية.

المتطلبات التقنية:
- Full Stack حقيقي.
- Frontend احترافي.
- Backend API layer.
- قاعدة بيانات.
- Authentication اختياري في MVP، لكن صمم البنية لدعمه لاحقًا.
- Responsive Design.
- Clean architecture.
- Error handling.
- Loading states.
- API service layer منفصلة.
- Environment Variables للمصادر والمفاتيح.

أول نسخة MVP:
ابدأ بالآتي:
1. Landing Page بسيطة واحترافية.
2. صفحة عرض المصحف.
3. قائمة السور.
4. عرض صفحات المصحف.
5. الضغط على آية لعرض تفسير ابن كثير.
6. حفظ آخر صفحة.
7. إضافة Bookmark.
8. بحث بسيط بالسورة.
9. إعدادات الوضع الليلي والنهاري.
10. صفحة مصادر البيانات.

قيود مهمة جدًا:
- لا تستخدم نص قرآن غير موثوق.
- لا تستخدم صور مصحف من مصدر غير واضح الترخيص.
- لا تخلط التفسير مع النص القرآني.
- لا تعرض تفسيرًا غير مطابق للآية.
- لا تضف محتوى ديني من عندك.
- لا تستخدم بيانات وهمية للآيات في النسخة النهائية.
- إذا لم يتوفر API موثوق لصور الصفحات، ابنِ الواجهة بحيث تكون جاهزة للربط وضع placeholder واضح مع طبقة service منفصلة.

المطلوب منك قبل التنفيذ:
1. اكتب PRD مختصر وواضح.
2. اكتب خطة بناء مرحلية.
3. اكتب هيكل الصفحات.
4. اكتب هيكل قاعدة البيانات.
5. اكتب خطة API Integration.
6. ثم ابدأ بناء نسخة MVP مباشرة.

فكر قبل تجاوب، وطلع لي PRD + خطة بناء + برومبت Replit، ثم ابدأ بناء المشروع الآن.
